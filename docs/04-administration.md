# Администрирование базы данных

## Почему PostgreSQL

PostgreSQL — открытая объектно-реляционная СУБД с развитой поддержкой транзакций, внешних ключей, индексов, представлений и хранимых процедур. Для интернет-магазина это подходит тем, что данные хорошо структурированы, целостность критична (заказы, платежи, остатки), а нагрузка не требует нереляционных решений. PostgreSQL надёжен, легко администрируется и поддерживает все механизмы, которые нужны в проекте: ограничения целостности, роли и права, резервное копирование.

## Развёртывание

База разворачивается последовательным выполнением SQL-скриптов из папки `sql/` через клиент `psql`. Сначала создаётся сама база данных, затем таблицы, ограничения, индексы, роли и права, после чего загружаются тестовые данные. Подробный порядок описан в README.

Базу можно запустить на локальном сервере, в виртуальной машине, в контейнере Docker или в управляемом облачном сервисе вроде Amazon RDS или Yandex Managed Service for PostgreSQL.

## Подключение

Стандартный порт PostgreSQL — 5432. Подключаться можно от имени суперпользователя `postgres` для администрирования или от имени отдельных ролей приложения для обычной работы.

Пример подключения:

```bash
psql -h localhost -p 5432 -U shop_admin -d shopdb
```

Параметры подключения вынесены в переменные окружения (`PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE`, `PGPASSWORD`), чтобы не хранить пароли в коде и скриптах.

## Пользователи и роли

На уровне кластера создаются четыре роли базы данных: `shop_admin`, `shop_manager`, `shop_operator`, `shop_readonly`. К ним привязываются демонстрационные пользователи для входа. Права настраиваются по принципу минимальных привилегий: администратор получает полный доступ, менеджер работает с товарами и заказами, оператор меняет только заказы и доставки, а роль только для чтения может лишь читать данные. Полный список прав — в файле `sql/05-roles-and-permissions.sql`.

## Разграничение доступа

Права выдаются командами `GRANT` и отменяются `REVOKE`. Администратор имеет все привилегии на таблицы и последовательности схемы `public`. Менеджер может вставлять, обновлять и удалять товары, категории, заказы и позиции, а остальные таблицы только читать. Оператор читает все таблицы, но может обновлять только заказы и доставки. Readonly-роль ограничена только `SELECT`. Это предотвращает случайное или умышленное изменение данных сотрудниками, которым это не нужно по должности.

## Обслуживание и контроль

Регулярные задачи администратора:

- `VACUUM ANALYZE` — очистка мёртвых кортежей и обновление статистики, чтобы оптимизатор выбирал эффективные планы запросов.
- `REINDEX` — перестроение индексов при фрагментации.
- Мониторинг активных сессий через представление `pg_stat_activity` и статистики по таблицам через `pg_stat_user_tables`.
- Проверка логов PostgreSQL на ошибки и медленные запросы.

Пример просмотра активных сессий базы `shopdb`:

```sql
SELECT pid, usename, application_name, state, query
FROM pg_stat_activity
WHERE datname = 'shopdb';
```

## Импорт и экспорт данных

Весь дамп базы делается утилитой `pg_dump`, восстанавливается через `psql` или `pg_restore`:

```bash
pg_dump -h localhost -U shop_admin -d shopdb > backup.sql
psql -h localhost -U shop_admin -d shopdb < backup.sql
```

Экспорт отдельной таблицы в CSV:

```sql
COPY products TO '/tmp/products.csv' DELIMITER ',' CSV HEADER;
```

Импорт из CSV:

```sql
COPY products FROM '/tmp/products.csv' DELIMITER ',' CSV HEADER;
```

Для удобства регулярного бэкапа и восстановления в папке `scripts/` лежат скрипты `backup.sh` и `restore.sh`, которые используют переменные окружения и не содержат секретов.
